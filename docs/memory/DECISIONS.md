# Architecture Decision Records

Формат: **Контекст / Решение / Последствия**. Append-only: не переписывай старые ADR,
если решение поменялось — добавь новый ADR со ссылкой «supersedes ADR-NNN».

---

## ADR-001: Одна таблица с полиморфным payload вместо таблицы на каждый тип

**Контекст.** Типы записей принципиально разные (email / article / site_change / ad),
у каждого свой набор полей. Соблазн — отдельная таблица на тип.

**Решение.** Одна `moderation_queue` с `type` + `payload JSON`. Отображение — полиморфное
по `type` (`www/app/render.php`), а не отдельные схемы.

**Последствия.** Простой единый список/фильтр/аудит, один UI. Цена — payload слабо
типизирован на уровне БД; валидация формы payload ложится на рендерер и API. Если
понадобится строгая схема на тип — добавим JSON Schema валидацию по `type`, не меняя таблицу.

## ADR-002: Идемпотентность через уникальный idempotency_key от агента

**Контекст.** Агенты ретраят при таймаутах/сетевых сбоях и могут залить дубль.
Два модера не должны одобрить одну запись дважды.

**Решение.** Уникальный `idempotency_key` (UNIQUE в БД). Повторный POST с тем же ключом
не создаёт новую запись, а возвращает существующую (`deduplicated: true`). Решения
модера — через `UPDATE ... WHERE status='pending'` с проверкой `rowCount()`.

**Последствия.** Агент обязан генерировать стабильный ключ. Дубли и гонки отсекаются
на уровне БД, а не «на честном слове». 409 при повторном ревью — ожидаемое поведение.

## ADR-003: Статус approved отделён от applied

**Контекст.** «Модер одобрил» и «деплой реально применил» — разные события.

**Решение.** `pending -> approved -> applied`, плюс ветки `rejected` и `failed`.
`approved` = ждёт воркер, `applied` = применено. `failed` — после N попыток.

**Последствия.** Видно, где затык: на ревью или на применении. Воркер поллит только
`approved`, модер видит, что одобренное ещё не применено.

## ADR-004: Vanilla PHP без фреймворка

**Контекст.** Сервис небольшой: очередь + CRUD + рендер + API.

**Решение.** Чистый PHP 8.5, без Laravel/Symfony. Слои: `public/index.php` (роутер) ->
`app/{core,api,ui,render,db,config}.php`.

**Последствия.** Минимум зависимостей, быстрый старт, легко читать. Цена — роутинг и
валидация руками. Если сильно разрастётся — выделим слой, но пока преждевременно.

## ADR-005: Fail-closed авторизация по токенам из ENV

**Контекст.** Публичный репозиторий: в коде не должно быть дефолтных «магических» токенов,
по которым можно случайно пустить в прод.

**Решение.** Токены только из ENV (`MODER_TOKEN_*`). Нет переменной -> роль отключена
(401/503), а не «пустим по дефолту». `.env` в `.gitignore`, в репо только `.env.example`.

**Последствия.** Нельзя запуститься «случайно открытым». Требуется явная настройка `.env`.
