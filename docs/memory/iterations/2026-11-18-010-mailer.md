# Iteration 010 — mailer (отправка писем через SMTP)

Date: 2026-11-18
Commit: f83b41e

## Goal
Агентам отключили прямой SMTP. Нужен безопасный отправитель: забирает approved
письма из moder и шлёт через SMTP, с гибкой скоростью и отдельными кредами на from.

## Changes
- `mailer/mailer.py` (Python 3.13, stdlib): claim email-items -> SMTP -> applied/failed.
  Отдельные SMTP-аккаунты на каждый from (`MAILER_ACCOUNTS` JSON), фолбэк на один.
- Гибкая скорость: `MAILER_DAILY_LIMIT`, `MAILER_BATCH_SIZE`, `MAILER_MODE=batch|spread`,
  `MAILER_WINDOW`+`MAILER_TZ`, `MAILER_MIN_GAP_SECONDS`, `MAILER_POLL_INTERVAL`.
- Безопасный дефолт: `MAILER_DRY_RUN=1` — только чтение (peek), не claim, статусы не меняет.
- `www/app/api.php`: `/api/devops/claim` принимает `types` и `project` (изоляция воркеров).
- `docker-compose.yml`: сервис mailer, изолированные env, volume `mailer_state`.
- `mailer/README.md`, `.env.example` — документация.

## Tests
- dry-run: видит approved, логирует from/to/subj, статус остаётся approved, attempts=0.
- боевой режим с неверным паролем: реальный ответ mail.ru (535, нужен app-password),
  status остаётся approved, apply_error заполнен, событие apply_error записано.
- build_message: выбор аккаунта по from, multipart plain+html, cc, Message-ID.
- ошибки: нет аккаунта / пустой to / нет from -> внятные ValueError.
- claim с types=email и types=other — каждый берёт только свои.
