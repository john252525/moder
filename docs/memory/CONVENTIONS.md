# Conventions

> Как здесь принято писать код. Чтобы агент не переизобретал и не спорил со стилем.

## PHP

- `declare(strict_types=1);` в каждом PHP-файле.
- PHP 8.5: используем `match`, `never`, именованные аргументы, `str_starts_with` и т.п.
- PSR-12 по форматированию, 4 пробела, без табов.
- **Типы везде**: параметры, возвраты, свойства. `never` для функций, которые делают `exit`.
- Никаких глобалок вне `core.php`. Конфиг — через `cfg()`. БД — через `db()`.
- Побочные `require`/`include` — только сверху файла. `config.php` — чистый `return [...]`
  без объявления функций и побочных эффектов (его require-ят многократно).

## Структура

    www/public/index.php   front controller: только роутинг
    www/app/core.php       общие хелперы, auth, json, uuid, фильтры
    www/app/api.php        REST API (/api/*)
    www/app/ui.php         серверный HTML для модера
    www/app/render.php     полиморфный рендер payload по type
    www/app/db.php         PDO + миграция
    www/app/config.php     конфиг (return array)
    www/app/schema.sql     схема БД (идемпотентная)

Новый тип записи: добавить в `config.php` -> `types` + `type_labels`, рендерер в
`render.php` (ветка `match`), схему payload описать в `API.md`. Таблицу НЕ менять.

## Безопасность

- **Эскейпинг:** любой пользовательский текст в HTML — только через `e()`. Без исключений.
- **HTML из payload** (email html) — рендерить в sandboxed `<iframe>`, не в основной DOM.
- **Токены/пароли** — только из ENV. В коде дефолтов нет (см. ADR-005).
- **Сравнение токенов** — только `hash_equals()`, не `===`.
- **SQL** — только prepared statements. Никакой конкатенации пользовательских данных.
- **JSON-вход** — парсить с `JSON_THROW_ON_ERROR`, валидировать типы полей.

## Ошибки

- API: бросаем `ApiError(http, code, message)`, ловим наверху, отдаём JSON `{error, message}`.
- Внутренние: `error_log()` + 500 без утечки деталей клиенту.
- UI: `flash()` для сообщений пользователю.

## Статусы и данные

- Статусы — строго из `config.php` -> `statuses`. Не хардкодить строки по коду.
- Переходы статусов — только через UPDATE с проверкой текущего статуса (оптимистичная блокировка).
- Аудит — каждое действие через `log_event()`.

## Bash-скрипты

- `#!/usr/bin/env bash` + `set -euo pipefail`.
- Секреты только из ENV, при отсутствии — `exit 2` с сообщением в stderr.
- Никаких захардкоженных токенов.

## Git

- Коммит-месседж: `iter NNN: <краткое summary>`.
- `.env`, `logs/`, `mysql/`, скриншоты — не коммитятся (см. `.gitignore`).
- После итерации — чеклист из `AGENTS.md`.
